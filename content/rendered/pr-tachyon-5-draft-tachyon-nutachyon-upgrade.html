#Terminology

The key words "MUST" and "MUST NOT" in this document are to be interpreted as described in BCP 14 1 when, and only when, they appear in all capitals.

The term "network upgrade" is defined in ZIP 200.2 "Testnet" and "Mainnet" are defined in the Zcash Protocol Specification.3

#Abstract

This ZIP defines the deployment of NuTachyon, activating the Tachyon shielded pool, its bundle format, and consensus-level proof aggregation.

#Motivation

Tachyon introduces a new shielded pool with recursive proofs and prunable nullifier state. Deployment requires coordinated changes to consensus validation, chain-state accounting, transaction encoding, and peer compatibility.

#Privacy Implications

NuTachyon introduces a separate shielded pool; activation does not migrate existing notes into it. See the shielded-protocol ZIP's Privacy and Security Implications and the bundle-format ZIP's Privacy Implications.

#Non-requirements

This ZIP does not specify P2P aggregation messages, covered-transaction discovery, or mempool and relay policy.

#Specification

#NuTachyon deployment

Under ZIP 200's activation mechanism,2 nodes MUST apply the NuTachyon rules starting with the block at ACTIVATION_HEIGHT (NuTachyon). The preceding block remains subject to the pre-upgrade rules.

NuTachyon activates the following specifications:

  • Tachyon Shielded Protocol: cryptographic constructions, proof statements, epochs, and pool-state rules.
  • Tachyon Bundle / Aggregate Transaction Format: bundle encodings, transaction-digest contributions, and bundle- and block-scoped validity rules.

Nodes MUST enforce both specifications.

#Network upgrade changes

#Tachyon pool initialization

The Tachyon pool is empty before the activation block. From activation onward, its pool height is a 32-bit unsigned integer equal to block height minus activation height. The activation block has pool height zero and begins epoch zero. Epoch boundaries and accumulator updates follow Epochs and Tachygram accumulator.

#Transaction format and digests

The choice between ZIP 248's extensible transaction format4 and a new transaction format remains open. No transaction version or version group ID is assigned here.

The bundle-format ZIP specifies the Transaction digest contributions, preserving the separation between effecting and authorizing data used by ZIP 244.5

#Chain value pool balance

The Tachyon chain value pool balance, an integer number of zatoshis, is the negated sum of all valueBalanceTachyon fields in the block chain, and is zero before activation. See Value balance and the binding signature.

Nodes MUST apply ZIP 209's non-negativity and total-supply checks with the Tachyon pool included.7 Proof aggregation does not merge value balances: each bundle's value balance contributes once, whether it carries a proof or a pointer.

#Chain history commitment

NuTachyon extends the ZIP 221 chain history commitment.8 The PoC adds history-tree fields for the earliest and latest Tachyon pool-state anchors and a count of transactions containing Tachyon bundles.9

#Backward compatibility

Before activation, upgraded and pre-NuTachyon nodes apply the same consensus rules and can remain connected. Nodes MUST NOT accept Tachyon bundles in blocks before activation. After activation, pre-NuTachyon software cannot validate the new consensus rules.

This ZIP does not require closing existing shielded pools.

#Reference implementation

Zakura PR #795 implements a NuTachyon proof of concept (PoC) behind zcash_unstable = "nutachyon". This ZIP references revision ec58f4bb.

The PoC uses v7 transactions; this does not settle the ZIP 248 decision. It schedules neither public Testnet nor Mainnet activation.

It implements Tachyon proof and signature verification, epoch-aware state, value-pool accounting, history commitments, and miner-side proof aggregation. Its mempool accepts Tachyon transactions whose proofs cover only their own actions; P2P aggregation and relay remain work in progress. These policies are not consensus requirements.
