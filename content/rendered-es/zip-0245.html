#Terminología

Las palabras clave "DEBE (MUST)" y "NO DEBE (MUST NOT)" en este documento se interpretan como se describe en BCP 14 [1] cuando, y solo cuando, aparecen en mayúsculas.

Los términos "rama de consenso", "época" y "actualización de red" en este documento se interpretan como se describe en el ZIP 200. [2]

#Resumen

Esta propuesta define cambios a los algoritmos de digesto de identificador de transacción y de firma del ZIP 244 [4] para acomodar la inclusión de extensiones transparentes de Zcash (TZE) según lo definido en el ZIP 222 [3].

#Especificación

#Digesto de TxId

El árbol de hashes definido por el ZIP 244 [4] se reestructura para incluir una nueva rama para los hashes de TZE. La rama tze_digest es la única adición nueva al árbol; header_digest, transparent_digest, sprout_digest y sapling_digest son como en el ZIP 244:

txid_digest
├── header_digest
├── transparent_digest
├── tze_digest
│   ├── tzein_digest
│   └── tzeout_digest
├── sprout_digest
└── sapling_digest

#txid_digest

El hash superior del árbol txid_digest se modifica respecto de la estructura del ZIP 244 para ser un hash BLAKE2b-256 de los siguientes valores

T.1: header_digest      (32-byte hash output)
T.2: transparent_digest (32-byte hash output)
T.3: tze_digest         (32-byte hash output)
T.4: sprout_digest      (32-byte hash output)
T.5: sapling_digest     (32-byte hash output)

El campo de personalización de este hash no se modifica respecto del ZIP 244.

#2: tze_digest

Un hash BLAKE2b-256 de los siguientes valores

T.2a: tzein_digest  (32-byte hash)
T.2b: tzeout_digest (32-byte hash)

El campo de personalización de este hash se establece en:

"ZTxIdTZE____Hash" (4 underscore characters)
2a: tzein_digest

Un hash BLAKE2b-256 de todas las entradas de TZE de la transacción, excluyendo los datos de testigo. Para cada entrada de TZE, los siguientes valores se agregan a este hash:

2a.i:  extension_id (CompactSize field encoding)
2a.ii: mode         (CompactSize field encoding)

El campo de personalización de este hash se establece en:

"ZTxIdTZEIns_Hash" (1 underscore character)
2a: tzeout_digest

Un hash BLAKE2b-256 de la codificación de campos de todas las salidas de TZE que pertenecen a la transacción.

El campo de personalización de este hash se establece en:

"ZTxIdTzeOutsHash"

#Digesto de firma

El algoritmo de creación del digesto de firma definido por el ZIP 244 [4] se modifica para incluir una nueva rama para los hashes de TZE. La rama tze_digest es la única adición nueva al árbol; header_digest, transparent_digest, sprout_digest y sapling_digest son como en el ZIP 244:

signature_digest
├── header_digest
├── transparent_digest
├── tze_digest
│   ├── tzein_digest
│   └── tzeout_digest
├── sprout_digest
└── sapling_digest

#signature_digest

Un hash BLAKE2b-256 de los siguientes valores

S.1: header_digest      (32-byte hash output)
S.2: transparent_digest (32-byte hash output)
S.3: tze_digest         (32-byte hash output)
S.4: sprout_digest      (32-byte hash output)
S.5: sapling_digest     (32-byte hash output)

El campo de personalización de este hash se establece en:

"ZcashTxHash_" || CONSENSUS_BRANCH_ID

ZcashTxHash_ tiene 1 carácter de guion bajo.

Este valor debe tener la misma personalización que el hash superior del árbol de digestos del identificador de transacción, para que sea posible firmar el identificador de la transacción en el caso de que no haya entradas transparentes.

#S.3: tze_digest

Este digesto es un hash BLAKE2b-256 de los siguientes valores de la entrada de TZE que se firma:

S.3a: prevout_digest (field encoding bytes)
S.3b: extension_id   (CompactSize field encoding)
S.3c: mode           (CompactSize field encoding)
S.3d: payload        (arbitrary bytes)
S.3e: value          (8-byte little endian value of the output spent by this input)

El campo de personalización de este hash se establece en:

"Zcash__TzeInHash" (2 underscore characters)

#Compromiso de datos de autorización

El árbol de hashes definido por el ZIP 244 [4] para los compromisos de datos de autorización se reestructura para incluir una nueva rama para los hashes de TZE. La rama tze_witnesses_digest es la única adición nueva al árbol; transparent_auth_digest, sprout_auth_digest y sapling_auth_digest son como en el ZIP 244:

auth_digest
├── transparent_scripts_digest
├── tze_witnesses_digest
├── sprout_auth_digest
└── sapling_auth_digest

#auth_digest

El hash superior del árbol auth_digest se modifica respecto de la estructura del ZIP 244 para ser un hash BLAKE2b-256 de los siguientes valores

A.1: transparent_scripts_digest (32-byte hash output)
A.2: tze_witnesses_digest       (32-byte hash output)
A.3: sprout_auth_digest         (32-byte hash output)
A.4: sapling_auth_digest        (32-byte hash output)

El campo de personalización de este hash no se modifica respecto del ZIP 244.

#2: tze_witnesses_digest

Un hash BLAKE2b-256 de la codificación de campos de los datos de testigo payload asociados con cada entrada de TZE que pertenece a la transacción.

El campo de personalización de este hash se establece en:

"ZTxAuthTZE__Hash" (2 underscore characters)
