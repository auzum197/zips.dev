---
name: zipreader-api
description: Query the zipreader JSON API (zipreader.org) for Zcash Improvement Proposals. Use when asked about a ZIP by number or title, a ZIP's status, owners or category, draft ZIPs, open pull requests to zcash/zips, what a PR changes or proposes, watched third-party proposals (Tachyon), what is new in zcash/zips, or Zcash network upgrades (Sapling, NU5, NU6, NU7).
---

Static JSON snapshots of the zcash/zips repository, regenerated by `scripts/sync.mts` on every push to `main` and daily at 05:23 UTC. Base URL: `https://zipreader.org` (the former `zips.auzum197.com` only serves a "moved" page). Every payload carries the upstream fields `repo`, `commit`, `commitShort`, `commitUrl`, `syncedAt`; data can lag upstream by up to a day, so quote `syncedAt` and `commitShort` when freshness matters.

`zips.json` (~90 KB), `prs.json` (~2.5 MB, carries file patches) and `external.json` (~190 KB) are too large to read whole. Pipe through `jq` with `-c`, `select`, `[:20]` or `head` and keep output bounded.

## Endpoints

| Path | Use for | Payload |
|---|---|---|
| `/api/meta.json` | freshness, commit | upstream fields only |
| `/api/zips.json` | catalogue: find, filter, list | `+ zips: ZipMeta[]` (137: 130 numbered ZIPs, 7 `draft-*` drafts). No `headings` |
| `/api/zips/<number>.json` | one numbered ZIP, with cross-refs | `ZipMeta + crossReferences, implementations: string[], upgrades: string[]`. No `headings`; drafts have no file here |
| `/api/prs.json` | open PRs to zcash/zips, newest first | `+ error: string|null, prs: PrMeta[]` (~80) |
| `/api/external.json` | watched third-party PRs (Tachyon) | `{syncedAt, sources: ExternalSource[], prs: PrMeta[]}` |
| `/api/upgrades.json` | network upgrades | `+ upgrades: Upgrade[]` (11) |

## Fields

`ZipMeta`: `slug` (`zip-0032` or `draft-<author>-<topic>`), `number` (null for drafts), `displayNumber`, `kind` (`zip`|`draft`), `filename`, `format` (`md`|`rst`), `title`, `status`, `revision`, `owners[]`, `credits[]`, `originalAuthors[]`, `category`, `created`, `license`, `discussionsTo`, `pullRequests[]` (URLs declared in the ZIP header), `upstreamPath`, `upstreamUrl`, `wordCount`, `rendered`, `abstract` (present but currently an empty string for every ZIP; do not rely on it).

`status` is free text. Simple values: `Draft`, `Proposed`, `Active`, `Final`, `Reserved`, `Obsolete`, `Withdrawn`. Multi-revision ZIPs carry compound strings such as `[Revision 0: Canopy, Revision 1: NU6] Final, [Revision 2: NU7] Proposed`, so match with `test(...)`, not `==`. `category` is also free text (`Consensus`, `Standards / Wallet`, `Informational`, ...).

`PrMeta`: `repo` (`zcash/zips`, or the watched repo for external PRs), `source` (null, or the `ExternalSource.id` such as `tachyon`), `number`, `title`, `author`, `createdAt`, `updatedAt`, `url`, `diffUrl`, `headRef`, `headRepo`, `headSha`, `additions`, `deletions`, `changedFiles`, `bodyExcerpt` (300 chars), plus:
- `zipRefs: number[]`, `draftRefs: string[]` — ZIPs/drafts the PR is about. Heuristic: union of changed `zips/*.md|rst` filenames, a `ZIP NNN` regex over title/body/branch, and ZIP headers that claim the PR. The regex produces false positives (e.g. `0` or an issue number); confirm with `files[].filename` or `previews[].slug`.
- `mapped` — `zipRefs` or `draftRefs` non-empty. `claimed` — some ZIP's `pullRequests` header lists this PR.
- `files[]: {filename, status (added|modified|removed|renamed), additions, deletions, patch}` — unified diff per file; `[]` with `filesTruncated: true` when the PR is large (>20 files or a 400 KB patch).
- `previews[]` — every ZIP/draft document the PR adds or modifies, rendered from the PR head, in file-list order: `{slug, filename, title, status, format, headings[{level,id,text}]}`. Empty when the PR touches no ZIP document or rendering failed.
- `preview` — the first element of `previews`, or null. Kept for backward compatibility; prefer `previews`.

`ExternalSource`: `id` (URL namespace, e.g. `tachyon`), `repo` (e.g. `tachyon-zcash/zips`), `label`, `note`, `error` (null unless that source's fetch failed). The external `prs[]` use the same `PrMeta` shape with `repo` and `source` set.

`Upgrade`: `id` (`overwinter`, `sapling`, `blossom`, `heartwood`, `canopy`, `nu5`, `nu6`, `nu61`, `nu62`, `nu63`, `nu7`), `name`, `code`, `mainnet`, `testnet` (ISO dates, null or absent when not yet activated), `status` (`proposed`, else null or absent), `summary`, `zips: number[]`.

## Recipes

```sh
B=https://zipreader.org

# Freshness: which upstream commit, synced when
curl -s $B/api/meta.json | jq -c '{commitShort, syncedAt}'

# One ZIP by number (includes cross-refs, implementations, upgrades)
curl -s $B/api/zips/32.json | jq -c '{number,title,status,category,owners,upgrades,implementations,crossReferences}'

# Find ZIPs by title keyword
curl -s $B/api/zips.json | jq -c '.zips[] | select(.title|test("hierarchical";"i")) | {number,slug,kind,title,status}'

# List by status / category / owner (first 20)
curl -s $B/api/zips.json | jq -c '[.zips[] | select(.status|test("proposed";"i")) | {number,title,status}][:20][]'
curl -s $B/api/zips.json | jq -c '[.zips[] | select(.category|test("wallet";"i")) | {number,title,category}][:20][]'
curl -s $B/api/zips.json | jq -c '[.zips[] | select(.owners|join(",")|test("grigg";"i")) | {number,title}][:20][]'

# Draft ZIPs (unnumbered)
curl -s $B/api/zips.json | jq -c '.zips[] | select(.kind=="draft") | {slug,title,status,owners}'

# Open PRs, newest first (first 20); first line is .error
curl -s $B/api/prs.json | jq -c '.error, (.prs | sort_by(.updatedAt) | reverse | .[:20][] | {number,title,author,updatedAt,zipRefs,draftRefs,docs:[.previews[].slug]})'

# PRs touching a given ZIP number (by ref, then by rendered document)
curl -s $B/api/prs.json | jq -c --argjson n 32 '.prs[] | select(.zipRefs|index($n)) | {number,title,updatedAt,claimed,url}'
curl -s $B/api/prs.json | jq -c '.prs[] | select(any(.previews[]; .slug=="zip-0032")) | {number,title}'

# PRs that change more than one ZIP/draft, with every document
curl -s $B/api/prs.json | jq -c '.prs[] | select(.previews|length>1) | {number,title,docs:[.previews[] | "\(.slug) [\(.status)]"]}'

# New proposals: PRs that add a ZIP/draft document (what the /new/ page shows)
curl -s $B/api/prs.json | jq -c '.prs[] | select(any(.files[]; .status=="added" and (.filename|test("^zips/(zip-[0-9]{4}|draft-[a-z0-9-]+)\\.(md|rst)$")))) | {number,title,author,updatedAt,zipRefs,draftRefs}'

# One document of a PR: title, status, headings (pick the slug from .previews)
curl -s $B/api/prs.json | jq -r --argjson n 1429 --arg s draft-marek-compact-block-relay '.prs[] | select(.number==$n) | .previews[] | select(.slug==$s) | "\(.title) [\(.status)] \(.filename)", (.headings[] | ("#"*.level)+" "+.text)'

# A PR's changed files, then a bounded slice of one patch
curl -s $B/api/prs.json | jq -r --argjson n 1429 '.prs[] | select(.number==$n) | .filesTruncated, (.files[] | "\(.status) \(.filename) +\(.additions)/-\(.deletions)")'
curl -s $B/api/prs.json | jq -r --argjson n 1429 '.prs[] | select(.number==$n) | .files[1].patch' | head -60

# Watched third-party PRs (e.g. Tachyon drafts): sources, then each PR's documents
curl -s $B/api/external.json | jq -c '.sources[] | {id,repo,label,error}'
curl -s $B/api/external.json | jq -c '.prs[] | {source,repo,number,title,updatedAt,docs:[.previews[] | "\(.slug) [\(.status)]"]}'

# A ZIP's headings (not in the JSON; read the anchors on the rendered page)
curl -s $B/zip/32/ | grep -oE '<h[1-4][^>]*id="[^"]+"' | sed -E 's/<h([1-4])[^>]*id="([^"]+)"/h\1 \2/'

# Network upgrades and their ZIPs
curl -s $B/api/upgrades.json | jq -c '.upgrades[] | {id,name,code,mainnet,status,zips}'
```

## Linking results

Pages on `https://zipreader.org`:
- numbered ZIP: `/zip/<number>/` (e.g. `/zip/32/`)
- draft: `/drafts/<slug>/` with the full slug (e.g. `/drafts/draft-arya-jvff-p2p-quic-transport/`)
- PR overview, listing every changed document: `/prs/<number>/` — exists only when `previews` is non-empty; otherwise link `url` (GitHub)
- one rendered document of a PR: `/prs/<number>/<slug>/` (e.g. `/prs/1443/zip-0248/`)
- watched third-party PRs: `/external/`, `/external/<source>/`, `/external/<source>/<number>/`, `/external/<source>/<number>/<slug>/` (e.g. `/external/tachyon/5/draft-tachyon-bundle-format/`)
- new proposals: `/new/`; all open PRs: `/prs/`; all drafts: `/drafts/`
- upgrade: `/upgrades/<id>/` (e.g. `/upgrades/nu7/`)
- upstream source: `upstreamUrl` (pinned to the synced commit)

## Caveats

- `prs.json.error` is non-null when the GitHub fetch failed and no snapshot under 24 h old could be reused; `prs` is then empty or stale. Check it before reporting "no open PRs". `external.json` carries the same per-source `error`.
- Headings are shipped only in `prs[].previews[].headings`; for a merged ZIP use the page-anchor recipe above.
- Patches in `files[].patch` can run to 100 KB per file. Always slice with `head` or `.[:N]`.
- `preview` (singular) is only the first changed document. A PR such as 1443 changes five ZIPs; use `previews` to see them all.
